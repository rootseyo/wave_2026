🚀 JEditor 마이그레이션 실행 순서 가이드

Windows 터미널(PowerShell / 명령 프롬프트)에서 jeditor 폴더로 이동한 뒤, 복사 버튼으로 명령어를 한 줄씩 실행하세요. Python 3의 python 명령을 사용합니다. py를 사용하는 환경에서는 첫 단어만 바꾸세요.

1. 메인 작업: 이슈 전체 필드 마이그레이션 (HTML ➔ ADF)

Step 1. 프로젝트 목록 반영 ➔ Step 2. DB 데이터 추출 ➔ Step 3. 현황 분석(선택) ➔ Step 4. Cloud ADF 변환
Step 1. 대상 프로젝트 키 SQL 반영 필수

../projects.txt의 대상 프로젝트 목록을 SQL 쿼리 파일(jeditor_mysql_queries.sql)에 반영합니다.

python step1_update_sql_projects.py
📥 입력: ../projects.txt 📄 갱신: jeditor_mysql_queries.sql
Step 2. Jira DC DB에서 HTML 데이터 추출 필수

대상 프로젝트의 본문(Description), 환경(Environment), 커스텀 필드의 모든 HTML/JEditor 데이터를 고속 JSONL 포맷(data.jsonl)으로 추출합니다.

대화형 실행 (Enter를 누르면 기본값 data.jsonl)

python step2_query_runner.py

또는 프롬프트 없이 단일 파일로 추출

python step2_query_runner.py --no-prompt --single-file
📥 쿼리: jeditor_mysql_queries.sql 📄 출력: data.jsonl (또는 data.html / data_projects/)
Step 3. 추출 데이터 통계 대시보드 확인 선택

추출된 data.jsonl(또는 data.html)의 프로젝트별·필드별 건수를 대시보드(data_dashboard.html)로 확인합니다.

python step3_analyze_data_html.py
📥 입력: data.jsonl (또는 data.html 자동 감지) 📊 출력: data_dashboard.html
Step 4. HTML ➔ ADF 변환 및 Jira Cloud 반영 필수 (핵심)

추출된 이슈 데이터를 ADF로 변환하고 첨부파일/이미지를 포함해 Jira Cloud에 업데이트합니다.

대화형 마법사 (환경 / 실행 모드 선택)

python step4_convert_adf.py

특정 이슈 1건 미리보기 (PROJ-123을 실제 이슈 키로 변경)

python step4_convert_adf.py --dry-run PROJ-123

특정 이슈 1건 실제 반영

python step4_convert_adf.py PROJ-123
📥 입력: data.jsonl (또는 data.html) + id-mappings-jira-classic-customField.html 📑 리포트: convert_adf_reports/index.html

2. 부가 작업 A: 커스텀 필드 기본값(Default Value) 찾아서 설정 바꾸기

커스텀 필드 기본값·Renderer 조회 (Step 5 실행 전 필수) 관리자 설정 변경용

HTML·일반 텍스트 기본값과 컨텍스트·이슈 유형·Renderer 설정을 조회합니다. default_values.html과 Step 5 비교용 default_values.json을 생성합니다. 이전 기본값이 있는 범위는 템플릿 이관보다 우선합니다. 터미널에 단계·배치·건수·소요 시간이 표시되고, SQL 처리 중에는 10초마다 진행 로그가 나옵니다. 기본값은 20개 프로젝트씩 순차 조회, 배치 간 0.5초 대기, 쿼리당 120초 제한입니다.

1) DB에서 HTML 기본값 설정 목록 추출

python run_default_values.py

DB가 바쁠 때: 배치를 줄이고 대기 시간 늘리기

python run_default_values.py --batch-size 5 --cooldown 2 --query-timeout 60

2) Cloud 설정 바로가기 링크가 포함된 대시보드 생성

python make_default_values_dashboard.py default_values.html
📥 쿼리: jeditor_default_values_all.sql 📊 출력: default_values.html, default_values.json, default_values_dashboard.html

3. 부가 작업 B: JEditor 템플릿 → Dynamic Forms Cloud

Step 5. JEditor 전용 템플릿(AO_BF4748) 리포트 생성 템플릿 확인용

기본 대상은 스크립트 상위 폴더의 projects.txt입니다. --project ATCU,BDD를 지정하면 해당 목록을 우선 사용합니다. 목록이 없거나 비어 있으면 실행을 중단합니다. 먼저 python run_default_values.py를 실행하세요. 기본값 전체 중복은 제외하고 일부 중복·범위 불명확·Renderer 미확인도 검토 제외합니다. 기본값이 없으며 대상 범위에 JEditor Renderer가 적용된 템플릿만 이관 후보가 됩니다. JEditor 템플릿을 추출하고 Visibility와 Autofill의 필드·이슈 유형 ID를 비교합니다. Visibility의 All·ALL은 전체 범위로 인정하여 Autofill 대상을 모두 포함하는 것으로 처리합니다. Autofill 이슈 유형의 ALL도 전체 이슈 유형으로 인식합니다. Autofill이 ALL이면 Visibility 이슈 유형도 ALL이어야 범위를 충족합니다. 빈 값·설정 누락은 ALL로 간주하지 않습니다. PASS(일치 또는 ALL 포함), REVIEW(범위·그룹 제한 검토), MISMATCH(범위 불일치), UNKNOWN(설정 누락·해석 불가)을 리포트에 표시합니다. 자동 채우기가 활성화되고 본문이 있으며 PASS인 항목만 마이그레이션 대상입니다.

python step5_check_jeditor_templates_sql.py --env ops
📥 쿼리: jeditor_template_queries.sql 📊 출력: template_report.html
Import 파일 생성 및 적용 테스트 환경에서 실행

실제 데이터로 만든 Step 5 리포트와 대상 Cloud의 필드 ID 매핑 파일을 준비한 뒤 실행합니다. 현재 저장소의 예제 리포트는 사용하지 마세요.

python build_dynamic_forms_import.py

기본 입력은 template_report.html과 id-mappings-jira-classic-customField.html입니다. 매핑 파일은 현재 폴더에서 먼저 찾고, 없으면 상위 폴더에서 찾습니다. Export 샘플 JSON은 필요 없습니다. 매핑 파일은 대상 Cloud 환경의 것을 사용하세요. ATCU만 생성하려면 뒤에 --project ATCU를 붙이세요.

📄 출력: dynamic_forms_import/프로젝트/Cloud필드ID/값해시/import.json 🔎 매핑 확인: mapping-report.json

프로젝트 + 매핑된 필드 + 본문 값마다 import.json 하나를 만듭니다. 동일 조합은 하나로 합치고, 다른 값은 별도 폴더에 저장합니다. 최신 Step 5에서 설정 검증 PASS, 기본값 우선·Renderer 검증 PASS 및 마이그레이션 대상으로 판정된 템플릿만 처리합니다. 이전 리포트는 Step 5를 다시 실행해 갱신하세요. 댓글(comment)은 제외하고 나머지 필드는 계속 생성합니다. 제외 내역은 mapping-report.json에 기록합니다. 필드 매핑 누락·중복이 있으면 생성을 중단합니다. 재실행 시 기존 출력 폴더를 사용하며, 교체 안내 후 동일 경로의 import.json과 mapping-report.json을 덮어씁니다. 이번에 생성하지 않는 이전 파일은 유지됩니다.

필요한 import.json을 대상 Dynamic Forms 설정에서 Import → Replace fields로 불러오고, draft를 확인한 뒤 APPLY CHANGES를 누릅니다. 같은 필드에 다른 파일을 다시 import하면 기존 규칙이 교체됩니다.

파일에는 이슈 유형·가시성 조건을 넣지 않습니다. 원본 정보는 mapping-report.json에서 확인하고 적용 범위는 대상 설정에서 지정하세요. Cloud 필드 타입은 기본적으로 textarea로 가정합니다. 실제 타입을 export 정보로 검증하려면 --sample "export파일경로.json"을 추가하세요.
