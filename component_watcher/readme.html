🚀 Jira DC ➔ Jira Cloud ✨ Safe Scan & Migration 🔍 Automated Verification 📊 Interactive HTML Dashboard 🛡️ Fail-Safe Protection

Jira Component Watcher Migration & Verification Toolkit

Jira Data Center 환경의 Component Watcher 플러그인 설정을 조회·분석하고, 사용자/그룹/이벤트 매핑을 거쳐 Jira Cloud로 안전하게 마이그레이션하며, 데이터 정합성을 전수 검증하는 엔지니어링 툴킷입니다.

📌 개요 및 아키텍처 ⚡ 표준 실행 워크플로우 🔍 1. 프로젝트 안전 스캔 (scan_projects.py) 🚀 2. 마이그레이션 엔진 (migrate.py) ✅ 3. 정합성 검증 (verify_migration.py) 📋 이벤트 매핑 규격 ⚙️ 환경 설정 (.env) 🛡️ 안전 수칙 및 트러블슈팅

📌 개요 및 아키텍처 (Overview & Architecture)

Component Watcher는 특정 컴포넌트(Component)에 이슈가 생성, 수정, 할당되거나 상태/댓글/작업로그가 변경될 때 지정된 사용자 또는 사용자 그룹에 자동으로 알림을 전송하는 Jira 플러그인입니다.

Jira Data Center에서 Cloud로 이전할 때, 온프레미스 계정명(Username)을 Cloud 표준(Email/Account ID)으로 매핑하고, 숫자형 Event ID를 Cloud URN 형식으로 변환하여 Cloud Component Watcher REST API에 동기화해야 합니다.

🔍 사전 분석 & 시각화

Jira DC의 컴포넌트 와쳐 설정을 조회하여 프로젝트별 사용자/그룹 현황 및 통계를 인터랙티브 HTML 대시보드로 즉시 확인합니다.

Read-Only Safe Mode

🚀 안전한 3단계 마이그레이션

Dry-Run 시뮬레이션을 통해 충돌 및 사전 등록 여부를 파악한 뒤, 선별적으로 Cloud API에 안전하게 전송합니다.

Dry-Run / Real-Run / API Test

✅ 전수 정합성 자동 검증

DC와 Cloud 양쪽의 와쳐 사용자(이메일), 그룹, 이벤트 타입을 컴포넌트 단위로 1:1 대조하여 엑셀 호환 CSV 리포트를 생성합니다.

🔍 Step 1. 대상 프로젝트 안전 스캔 (scan_projects.py)

scan_projects.py — 읽기 전용 사전 조사 및 인터랙티브 대시보드 생성 Scan & Dashboard

Jira Cloud에 어떤 변경도 가하지 않는 완전한 읽기 전용(Read-Only Safe Mode) 도구입니다. 지정된 프로젝트 목록의 Component Watcher 설정 현황(컴포넌트 수, 와쳐 지정 사용자/그룹, 이벤트)을 조회하고 사용자 이메일을 일괄 변환하여 인터랙티브 대시보드(dashboard.html)를 생성합니다.

주요 실행 명령어

# 1. 대화형 환경 선택 실행 (기본 ../projects.txt 사용)
python3 scan_projects.py

# 2. STG 환경 대상 즉시 스캔 (프롬프트 생략: -y)
python3 scan_projects.py --env stg -y

# 3. OPS 환경 대상 및 특정 프로젝트 목록 파일 지정 실행
python3 scan_projects.py --env ops --file ./custom_projects.txt -y

CLI 옵션 매개변수

옵션 타입 기본값 설명
--env stg | ops 대화형 선택 스캔 대상 Jira DC 환경 (Stage 또는 Operations)
--file 경로 (string) ../projects.txt 대상 프로젝트 키 목록 텍스트 파일 경로
-y, --yes 플래그 False 안전 스캔 동의 프롬프트 없이 즉시 진행

주요 기능 및 산출물

  • 사용자 이메일 캐싱: 동일 사용자의 반복 조회를 방지하여 Jira DC API 부하 최소화
  • 보안 인증 실패 방지: HTTP 401 발생 시 계정 잠금을 방지하기 위해 즉시 작업을 안전하게 중단
  • dashboard.html: TOP 5 와쳐 보유 프로젝트, 와쳐 유형 비율(사용자 vs 그룹), 프로젝트별/컴포넌트별 상세 테이블 및 실시간 검색/필터 기능 내장
📥 입력: ../projects.txt, ../env
📊 출력: 콘솔 요약, dashboard.html, log.txt
🔒 영향도: Jira DC 조회 전용 (Cloud 데이터 변경 전혀 없음)

🚀 Step 2. 컴포넌트 와쳐 마이그레이션 엔진 (migrate.py)

migrate.py — 설정 변환 및 Jira Cloud REST API 동기화 Migration Engine

Jira Data Center의 Component Watcher 설정을 스캔 및 분석한 후, 대화형 확인("스캔 후 migration 하겠습니까?")을 거쳐 Jira Cloud REST API로 안전하게 마이그레이션합니다.
사용자 할당에 이슈가 발생하더라도 설정 값(이벤트 규칙, 그룹)을 우선 마이그레이션하고, 사용자 할당을 분리하여 이슈가 발생한 사용자별로 상세 진단 로그를 남깁니다.

주요 실행 명령어

# [표준 실행] 스캔 ➔ 요약 및 대시보드(dashboard.html) 확인 ➔ 마이그레이션 진행 여부 질의 (Y/N)
python3 migrate.py --source-env stg --target-env sandbox

# [스캔 전용 모드] 스캔 및 대시보드 리포트만 생성 (Cloud 마이그레이션 미수행)
python3 migrate.py --source-env stg --target-env sandbox --scan-only
# 또는 기존 scan_projects.py 실행 시 migrate.py 스캔 엔진이 통합 실행됩니다:
python3 scan_projects.py --env stg

# [비대화형/자동 모드] 질의 프롬프트 없이 스캔 후 즉시 마이그레이션 진행
python3 migrate.py --source-env stg --target-env sandbox -y

# [연결 테스트] Cloud REST API 연결 및 엔드포인트 응답 점검
python3 migrate.py --source-env stg --target-env sandbox --test-cloud

CLI 옵션 매개변수

옵션 타입 기본값 설명
--source-env, --env stg | ops 대화형 선택 소스 Jira DC 환경 선택
--target-env, --target sandbox | ops 대화형 선택 대상 Jira Cloud 환경 선택 (stg 입력 시 sandbox로 자동 매핑)
--scan-only, --dry-run 플래그 False 스캔 및 대시보드(dashboard.html) 생성만 수행하고 마이그레이션 미수행
-y, --yes 플래그 False 스캔 후 마이그레이션 진행 확인 프롬프트 없이 즉시 마이그레이션 실행
--real-run 플래그 False 스캔 후 바로 마이그레이션 실행 (기존 호환용)
--test-cloud 플래그 False Target Jira Cloud REST API 연결 및 엔드포인트 응답 테스트
--file 경로 ../projects.txt 처리 대상 프로젝트 키 목록 파일
--project 문자열 None --test-cloud 실행 시 단일 테스트 대상 프로젝트 키 지정

상태 판정 및 중복 처리 로직

상태 코드 설명 및 조치
DRY-RUN Dry-Run 모드로 실행되어 데이터 추출 및 변환 검증이 완료된 상태
MATCH Jira Cloud에 이미 설정이 존재하며, DC 설정(사용자, 그룹)과 100% 동일하여 추가 전송 생략
MISMATCH Jira Cloud에 이미 설정이 존재하지만 DC 설정과 차이가 있음 (기존 설정 보호를 위해 자동 덮어쓰기 방지)
SUCCESS Jira Cloud에 신규 컴포넌트 와쳐 설정이 정상적으로 생성됨 (HTTP 200/201)
EXISTING Cloud API 전송 중 이미 등록된 설정으로 반환됨
FAILED 네트워크 오류 또는 권한/엔드포인트 에러로 마이그레이션 실패
📥 입력: ../projects.txt, ../env
📄 출력: report.html (마이그레이션 상세 리포트), log.txt
⚙️ 엔드포인트: /rest/componentwatcher/1.0/config/configurations/{projectKey}

✅ Step 3. 마이그레이션 정합성 전수 검증 (verify_migration.py)

verify_migration.py — DC vs Cloud 설정 1:1 대조 및 CSV 리포트 생성 Verification & Audit

마이그레이션 완료 후 Jira DC와 Jira Cloud 양쪽 시스템에서 동일 프로젝트의 컴포넌트 와쳐 설정을 동시에 가져와 와쳐 사용자(이메일), 그룹 목록, 이벤트 설정이 완벽하게 일치하는지 전수 검증합니다.

주요 실행 명령어

# 1. 기본 실행 (대화형 환경 선택 -> report.csv 생성)
python3 verify_migration.py

# 2. 프로젝트 파일 및 출력 CSV 경로 직접 지정 실행
python3 verify_migration.py --file ../projects.txt --output ./migration_verification_report.csv

CLI 옵션 매개변수

옵션 타입 기본값 설명
--file 경로 ../projects.txt 검증 대상 프로젝트 목록 파일 (부재 시 ../jeditor/projects.txt 폴백)
--output 경로 report.csv 검증 결과가 저장될 CSV 파일 경로 (Excel 호환 UTF-8 BOM 인코딩)

검증 판정 기준 (Verification Status)

  • MATCH: DC와 Cloud 양쪽에 컴포넌트가 존재하며 사용자(이메일), 그룹, 이벤트가 100% 일치함
  • MISMATCH: 양쪽에 존재하나 사용자 수, 그룹 명단, 또는 이벤트 구성에 차이가 있음 (상세 불일치 내역이 Details 열에 기록됨)
  • MISSING_IN_CLOUD: DC에는 와쳐가 설정되어 있으나 Cloud에는 등록되지 않음
  • MISSING_IN_DC: Cloud에는 설정되어 있으나 DC에는 존재하지 않음
  • DC_FETCH_ERROR: DC API 통신 오류 또는 권한 문제로 설정을 불러오지 못함
📥 입력: ../projects.txt, ../env
📊 출력: 콘솔 통계, report.csv (UTF-8 with BOM)
📑 CSV 헤더: Project Key, Component Name, Status, DC Watchers, Cloud Watchers, Watchers Match, DC Groups, Cloud Groups, Groups Match, DC Events, Cloud Events, Events Match, Details

📋 이벤트 매핑 규격 (Event Type Mapping Reference)

Jira Data Center의 Component Watcher는 내부 정수 ID로 이벤트를 관리하며, Jira Cloud는 Atlassian 표준 URN 문자열 형식을 사용합니다. 툴킷은 아래 규격에 맞춰 양방향 자동 매핑을 수행합니다.

DC Event ID Cloud Event URN String 이벤트 명칭 및 발생 조건
1 avi:jira:created:issue 이슈 생성 (Issue Created) — 컴포넌트가 지정된 새 이슈가 등록될 때
2 avi:jira:updated:issue 이슈 수정 (Issue Updated) — 이슈 필드나 정보가 변경될 때
3 avi:jira:assigned:issue 담당자 변경 (Issue Assigned) — 이슈의 담당자가 변경될 때
4 avi:jira:updated:resolution 해결책 변경 (Issue Resolved) — 해결책(Resolution)이 지정되거나 변경될 때
5 avi:jira:updated:status 상태 변경 (Status Updated) — 워크플로우 상태 전이가 발생할 때
6 avi:jira:commented:issue 댓글 작성 (Issue Commented) — 이슈에 새 댓글이 등록될 때
10 avi:jira:created:worklog 작업로그 등록 (Worklog Created) — 소요 시간 작업로그가 기록될 때
15 avi:jira:updated:worklog 작업로그 수정 (Worklog Updated) — 기존 작업로그가 수정될 때
16 avi:jira:deleted:worklog 작업로그 삭제 (Worklog Deleted) — 기존 작업로그가 삭제될 때

🛡️ 안전 수칙 및 트러블슈팅 (Safety & Troubleshooting)

🔒 계정 잠금 방지 (401 Interceptor)

비밀번호나 API 토큰 만료로 인한 계정 잠금 사태를 방지하기 위해, 최초 HTTP 401 인증 실패 감지 즉시 전체 루프를 안전하게 강제 중단합니다.

🔄 지능형 재시도 (Exponential Backoff)

순간적인 네트워크 지연이나 Rate Limit(429), 게이트웨이 오류(500, 502, 503, 504) 발생 시 최대 3회까지 지수 백오프 기반으로 자동 재시도합니다.

📝 자격증명 마스킹 진단 로그

log.txt 파일에 리다이렉트 체인 및 헤더 진단 정보를 상세히 기록하되 패스워드나 인증 토큰은 철저히 마스킹되어 안전합니다.

자주 발생하는 문제 및 해결 방안 (FAQ)

Q1. [인증 오류] Jira 인증 실패 (HTTP 401)가 발생하며 스크립트가 중단됩니다.

➔ ../env 파일의 계정 ID 또는 비밀번호/API 토큰이 올바른지 확인하세요. 사내 SSO/2FA가 적용된 경우 일반 비밀번호 대신 개인 액세스 토큰(PAT)을 발급받아 설정해야 할 수 있습니다.

Q2. SSL 인증서 오류(SSLError: certificate verify failed)가 발생합니다.

➔ 사내 사설 인증서를 사용하는 환경인 경우 ../env 파일에 JIRA_SSL_VERIFY=false를 추가하거나 실행 환경의 시스템 인증서 번들에 루트 인증서를 등록하세요.

Q3. Jira Cloud 대상 프로젝트에 컴포넌트가 등록되어 있지 않은 경우

➔ Component Watcher는 Jira 프로젝트 내에 해당 컴포넌트(Component)가 먼저 생성되어 있어야 와쳐 설정 등록이 가능합니다. 프로젝트 컴포넌트 동기화가 먼저 완료되었는지 확인하세요.

Q4. Excel에서 report.csv를 열었을 때 한글이 깨집니다.

➔ 본 툴킷의 verify_migration.py는 Microsoft Excel 한글 자동 인식을 위해 utf-8-sig(BOM 포함)로 저장하므로 별도 인코딩 변환 없이 바로 정상 열람이 가능합니다.
